# slipway-demo (project id `adlc-demo`)

Demo monorepo delivered end to end by the [slipway](https://github.com/integranz/slipway) Claude Code plugin, which implements the Agentic Delivery Lifecycle (ADLC). The project id `adlc-demo` names the Azure resources and image repositories and is intentionally unchanged.

| App | Path | Stack | Port | Health |
|---|---|---|---|---|
| api | `apps/api` | .NET 8 minimal API (`Api.sln`: `src/Api`, `tests/Api.Tests`) | 8080 | `/health` returns `{status, version, startedAt}` |
| web | `apps/web` | React 19 + Vite 8; served by nginx in the container once dockerized (dev server: 5173) | 8080 | `/` |

Versioning: [Nerdbank.GitVersioning](https://github.com/dotnet/Nerdbank.GitVersioning), one `version.json` **per app** (`apps/api/version.json`, `apps/web/version.json`; git tags `api/v<semver>`, `web/v<semver>`). Each app's patch number counts only commits touching that app's inputs, so a change to `apps/web` leaves the api version untouched, while `libs/dotnet/Demo.Contracts` (referenced by the api) bumps and rebuilds the api. CI stamps the version into both images (`-p:InformationalVersion` for the API, `VITE_APP_VERSION` for the web) so a deployment can be verified against its tag.

Local run:
```
ASPNETCORE_HTTP_PORTS=8080 dotnet run --project apps/api/src/Api   # http://localhost:8080/health (containers set this variable)
npm --prefix apps/web install && npm --prefix apps/web run dev   # http://localhost:5173 (proxies /api to :8080)
```
Tests: `dotnet test apps/api` and `npm --prefix apps/web test`.

Containers: `/slipway:dockerize <app>` builds one image; `VERSION=$(nbgv get-version -p apps/api -v SemVer2) docker compose up --build` runs both (api on :8080, web on :8081 proxying `/api/` to the api).

Delivery configuration, rules and workflows are generated by `/slipway:bootstrap`; `AGENTS.md` is the routing page for humans and agents.

Verified deployments: every `/slipway:verify <env> <tag>` run leaves its claim table in `.slipway/evidence/<tag>.md` (latest: [0.1.24](.slipway/evidence/0.1.24.md), 19/19 confirmed). Deployments themselves are applied only after a human approves the `dev` environment in GitHub Actions.

## Pipelines: one CI and one CD per app
| App | CI | CD | Triggers |
|---|---|---|---|
| api | `slipway-demo-api-ci` | `slipway-demo-api-cd` | `apps/api`, `libs/dotnet/Demo.Contracts`, its two workflow files, `_ci.yml`/`_cd.yml`, `infra/apps/api`, root `.dockerignore` |
| web | `slipway-demo-web-ci` | `slipway-demo-web-cd` | `apps/web`, its two workflow files, `_ci.yml`/`_cd.yml`, `infra/apps/web` |

A push to `main` runs only the CI of the apps whose inputs changed; on pull requests every app CI starts and its `changes` job skips the rest when the app is untouched (so the checks can be required on `main`). A green CI on `main` starts that app's CD into `dev` automatically; the apply still waits for a human on the `dev` environment. Each app has its own Terraform module and state under `infra/apps/<app>`; the Container Apps environment lives in `infra/foundation`. Details: `AGENTS.md` (Pipelines section) and `.claude/rules/pipelines.md`.
